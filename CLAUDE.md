# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

kasset is a keyboard-driven terminal music player (Rust, ratatui + crossterm UI, rodio audio, lofty tags) for a local music folder. Single binary crate, no workspace.

## Commands

```sh
cargo build                                   # needs libasound2-dev + pkg-config on Linux
cargo run -- [DIR]                            # open DIR (default: XDG music dir, ~/Music, then cwd)
cargo run -- --help                           # key summary lives in src/cli.rs
cargo test                                    # all unit tests (no sound hardware needed)
cargo test queue::                            # tests in one module
cargo test some_test_name                     # single test by name substring
cargo clippy --all-targets -- -D warnings     # must be clean; pedantic is on
cargo +1.89 build                             # MSRV check (rust-version = 1.89)
```

Whenever dependencies change, re-check `rust-version` against the highest dependency MSRV (`cargo metadata`).

CI (`.github/workflows/ci.yml`) runs clippy + tests on Linux, macOS and Windows plus an MSRV build. Releases: bump `version` in `Cargo.toml`, dry-run `gh workflow run Release --ref master` (also runs on PRs touching Cargo.toml/Cargo.lock/.cargo/release.yml; builds + packages, never publishes), then push tag `vX.Y.Z`; `release.yml` checks the tag matches, tests, builds 5 targets and publishes a GitHub Release. Code must stay warning-free on non-unix too (gate unix-only test helpers with `#[cfg(unix)]`). `.cargo/config.toml` links the MSVC C runtime statically so `kasset.exe` needs no VC++ Redistributable.

## Lints and code rules

- `unsafe_code = "forbid"`; clippy `all` + `pedantic` warn, plus `unwrap_used`, `expect_used`, `dbg_macro`, `todo`. Tests avoid `unwrap()` too (e.g. `unwrap_or_else(|never| match never {})`).
- Edition 2024. Every module starts with a `//!` doc comment explaining its role and invariants — keep them accurate when changing behaviour.
- Tags, file names and playlist contents are **untrusted input**. All text that reaches the screen must go through `text::sanitize` / `text::display_path`; decoders and tag readers run inside `panic_guard::quietly` so their panics become errors without printing over the TUI.
- Release profile uses `panic = "unwind"` (required for `catch_unwind` in `panic_guard`).

## Architecture

Data flows `main.rs` → `cli::resolve_root` → `terminal::ensure_terminal` → `Player::open` (fail fast with no audio device) → `library::scan` → `App::new(tracks, player, FsStore, …)` → `terminal::run` event loop.

Layering, from pure logic outward:

- `queue.rs` — pure play order (shuffle, repeat off/all/one). Plays a list of **items** (library indices, duplicates allowed) addressed by item position. Supports live edits (`remove_item`, `move_item`, `append_items`, `replace_items`); removing the playing item leaves the queue *detached* (it moves on to the removed item's successor, never back).
- `player.rs` — the `Audio` trait plus the rodio-backed `Player`. Everything above it is generic over `A: Audio` so tests use fakes (`test_support::SilentAudio`; `test_support::ToneAudio` reports a sine for the visualizer; `FakeAudio` in `playback.rs` tests can end/fail individual tracks). `Guarded` wraps every decoder: it turns decoder panics into the end of the track and is the visualizer's audio tap — it mixes frames to mono (tracking spans itself, re-reading the format only on a frame boundary) and hands 512-sample batches to the load's `TapBuffer` ring (newest `FFT_SIZE`) with `try_lock`, dropping them when busy, so the audio thread never blocks or allocates. The tap is upstream of the volume; a rate change clears it; each `load` gets fresh `SourceFlags`, so a fresh tap. `Audio::recent_samples` (default `None`) copies it out, with the load's `generation` (`Player` numbers loads); `Playback::recent_samples` passes it through.
- `playback.rs` — `Playback<A>` ties `Queue` to `Audio`: transport commands, auto-advance, skipping unplayable tracks, `Notice` status messages. A `Source` (library or a playlist) defines the current play order; playlist edits/reloads/renames/deletes are forwarded so the playing order stays consistent.
- `playlist.rs` + `playlist/{name,paths,store}.rs` — `.m3u8` files in `<root>/Playlists`. A playlist is kept as **raw lines with their own line endings** so saves only touch edited lines (comments, BOM, CRLF, unmatched entries, missing final newline survive). Non-UTF-8 or oversized files are parsed but read-only. `paths::Resolver` matches entries literal → `\`-as-separator → `canonicalize` (bounded). `store::FsStore` implements the `PlaylistStore` trait: atomic temp-file + rename saves, stamp check to never overwrite external changes (`ChangedOnDisk`), no-clobber create/rename via `hard_link`, symlinked playlists stay links, but only if the link target resolves inside `Playlists/` (else `ReadOnlyReason::LinksOutside`, re-checked in `save`). kasset must never write outside `Playlists/`.
- `bounded_read.rs` — the one reader for small untrusted files (playlists, `.lrc` sidecars): `read_limited(path, limit) -> (bytes, truncated, Metadata)` opens with `open_regular` (unix: `O_NONBLOCK|O_NOCTTY|O_CLOEXEC`, so a FIFO never blocks; elsewhere a regular-file check first), refuses anything but a regular file judged from the open handle, and reads at most `limit` bytes. The playlist store builds its `FileStamp` from the returned `Metadata`.
- `app.rs` — all UI state and key → action mapping, no terminal I/O; files only via `PlaylistStore`. `Focus` = Sidebar / Main, moved with `Tab`/`BackTab`; `view()` (the list keys act on) is derived from `(focus, open)`: the sidebar, the library, or the open playlist. The sidebar `ListState` has a fixed "Library" row at value 0 (never filtered out; playlist `i` is value `i + 1` — go through `selected_playlist()` / `sidebar_value_of()`). `open` is set only by `Enter` on a sidebar playlist and cleared by `Enter` on "Library", deleting it, or its file vanishing; renaming it reloads it under the new name. Playlists are listed in `App::new` and on every sidebar focus; the app's own edits patch the sidebar entry with `update_info`. Every status message goes through `App::notify` (within one key press an error is never hidden; same-level notices are joined). Each list keeps its own filter and selection. `Mode` = Normal / Search / Picker (add-to-playlist target) / NameInput (`NamePurpose::Create` for "New playlist…" or `NamePurpose::Rename` for `R`, prefilled with the current name) / ConfirmDelete (`D`: `y` deletes, any other key cancels) / Help (`?`: scroll keys move it, clamped to `keys::help_line_count() - help_rows`, where `help_rows` is fed from `ui::View` by `terminal::run` like `page_size`; any other key closes it and is consumed). Entry edits (`d`, `J`/`K`) are made on a copy of the open playlist, saved, then installed, so a failed or conflicting save leaves the screen unchanged. Visualizer state (`Visualizer`): `on` (start on; `v` in Normal mode toggles it, with an `Info` notice only while `!fits`), `fits`/`bars` fed back via `set_spectrum_layout`; `tick` runs the `Spectrum` only while `on && fits && bars > 0` (else resets it), passing samples only while `Playing` and the tap's `(generation, written)` changed within `STALE_AFTER` (250 ms). `visualizer_animating()` drives the frame rate. Lyrics state (`LyricsPane`): `on` (start on; `l` in Normal mode toggles it, with an `Info` notice only while `!fits`, naming `ui::LYRICS_MIN_WIDTH` 100), `fits` fed back via `set_lyrics_layout`; `tick` (after `playback.tick`) calls `lyrics::source::load` only while `lyrics_shown()` (`on && fits`) and the current track's **path** differs from `loaded_for` (seek/pause/replay never re-read); `loaded_for`/`lyrics` are dropped whenever the pane stops being shown, so showing it again re-reads. `lyrics_ready()` (cache belongs to the current track's path) gates `lyrics()`, so "No lyrics" never flashes before a load. `lyrics_generation()` counts loads (for the UI's wrap cache). `lyrics_deadline(now)`: while shown, `now` if a read is due (current track, `!lyrics_ready()`, so widening/showing never leaves the pane blank for a frame), else while `Playing` and synced, `now + max(next_change - position, LYRICS_MIN_WAIT)` (10 ms). `#[cfg(test)] set_lyrics_on` sets `on` with no notice. Entry points: `App::handle_key`, `App::tick`.
- `ui.rs` — renders `App` read-only. Body = sidebar + main pane at ≥ `TWO_PANE_MIN_WIDTH` (70) columns, else only the focused pane full width; draws from `sidebar_list()` / `main_list()`, never `visible()`/`selected()` (those are the focused list only). `ui::View` keeps `sidebar_offset` / `main_offset` (the sidebar's offset counts playlist rows; "Library" and its separator stay on top) and feeds back `page_size` (focused pane), `help_rows`, `spectrum_fits` / `spectrum_bars`, and `lyrics_fits` (width ≥ `LYRICS_MIN_WIDTH` 100, set every frame whether or not the pane is on). Lyrics pane: a third column right of the main pane when `app.lyrics_on()` and `lyrics_fits`, width `(body/3).clamp(LYRICS_WIDTH)` (28..48); the sidebar keeps its two-pane width, the main pane fills the rest; above the strip; never focused (unfocused border). It shows "Nothing playing" with no current track, nothing while `!app.lyrics_ready()`, "No lyrics" (both via `render_empty`), else `lyric_rows(lyrics, width)` — wrapped by drawn width (sum of grapheme-cluster widths) at spaces, over-wide words broken between clusters — cached in `View::lyrics_rows` keyed by `(App::lyrics_generation(), inner width)`; per frame only `current_rows` (`partition_point`) and `row_role` are computed: `PLAYING` (current line, all its rows) / `DIM` (past) / default. Synced scroll centres the whole current line (`synced_top`; its first row on top if taller than the pane), plain scroll is `span * pos_ms / dur_ms` in `u128` clamped to `span` (`plain_top`). Spectrum strip: the bottom `SPECTRUM_HEIGHT` (6) rows of the body when `app.visualizer_on()` and height ≥ `SPECTRUM_MIN_HEIGHT` (24), full width at every width, unfocused border, `bars = (inner_width + 1) / 2` (1-column bars, 1-column gaps), draws `min(levels.len(), bars)` bars in eighths (`█`, `▁…▇`) with `theme::SPECTRUM`. Sidebar marker comes from `App::sidebar_playing()` (only while a track is loaded). Popups centre over the whole body (panes and strip together); the `?` overlay centres over everything above the status line, sized to its widest line, and writes `help_rows` only while drawn. Now-playing is 3 rows (top rule, track line with right-aligned indicators that win over the title, custom `━╸─` progress line). The key bar is drawn from `keys::bar(context)`, cut at whole labels, `? help` right-aligned in Normal mode only. All styles come from `theme.rs` — no `Color`/`Modifier`/`Stylize` in `ui.rs` outside tests. Tested with ratatui `TestBackend`.
- `keys.rs` — the single key table `GROUPS` (D7) feeding `--help` (`help_text`), the help overlay (`help_lines`) and the key bar (`bar(BarContext)`).
- `theme.rs` — style roles (D8): `PLAYING`, `SELECTED_FOCUSED`/`SELECTED_UNFOCUSED`, `BORDER_*`, `DIM`, `ERROR`, … Named ANSI colours only; each colour has one meaning.
- `terminal.rs` — raw mode / alt screen setup and restore on every exit path (quit, error, signal, panic); redirects fd 2 to `/dev/null` while the UI is up so ALSA can't print over it. A second identical signal is an emergency exit. Each frame: tick, draw, feed back `page_size` / `help_rows` / `set_spectrum_layout` / `set_lyrics_layout`, then poll input until `next_deadline(frame_start, app.visualizer_animating(), app.lyrics_deadline(now))` — `ANIMATION_FRAME` (33 ms) while animating, else `FRAME` (250 ms), counted from the frame start, or the lyric deadline (next synced line, or at once while a lyrics read is due) if that is earlier.
- `visualizer.rs` — pure spectrum analysis (`rustfft`): `Spectrum::update(samples+rate, bars, now)` windows the newest `FFT_SIZE` (2048) mono samples, takes peak magnitudes in log-spaced bands from 40 Hz to `min(16 kHz, rate/2)`, maps −60…0 dB to 0…1; bars rise at once and fall linearly over `FALL_TIME` (1 s); a bar-count change resets the levels (count clamped to `MAX_BARS`). DC offset is removed and bin 0 never used. Levels are always finite and in `0..=1`.
- `lyrics.rs` — pure LRC parsing (no I/O): `parse(text) -> Option<Lyrics>` gives `Lyrics::Synced(Vec<Line { at, text }>)` (sorted by time, stable for equal times; one `Line` per leading `[mm:ss(.x{1,3})]` stamp, 1–6 minute digits) or `Lyrics::Plain(Vec<String>)` (file order, blank edges trimmed). `[tag:value]` headers (tag of ASCII alnum/`_`/`-`/`#`) are skipped before a timestamp; an untimed line is dropped only if it is nothing but `KNOWN_TAGS` headers (`ar`, `ti`, `offset`, …), so `[Chorus: Singer] la` stays text; `[offset:±N]` shifts times (positive = earlier), clamped to ±1 h, saturating at 0; other bracket text (`[Chorus]`) stays; `<mm:ss.xx>` word timings are stripped. With any timestamp, untimed lines are dropped; blank timed lines are kept as `""` (they end the previous line). Every text goes through `text::sanitize` (whitespace collapsed, cut to `MAX_TEXT_CHARS` 256); at most `MAX_LINES` (10 000) lines; arithmetic is checked/saturating and scanning linear, so crafted input can't panic, wrap or stall. `current(pos)` / `next_change(pos)` use `partition_point`. `lyrics/source.rs` does the I/O: `load(track) -> Option<Lyrics>` reads the first *readable* sidecar (`<stem>.lrc`, `<stem>.LRC`, then a sorted, case-insensitive-extension match from at most `MAX_DIR_ENTRIES` (10 000) folder entries; a directory/FIFO/dangling link counts as absent) through `bounded_read` capped at `MAX_LYRICS_BYTES` (1 MiB), decodes it (UTF-8 BOM, UTF-16 LE/BE BOM, else lossy UTF-8), and parses it even if that gives `None` (an empty sidecar hides tag lyrics); a truncated sidecar loses its last (possibly cut) line (split at `\n` or `\r`); without one it falls back to `library::lyrics_tag` (raw text of the first tag, primary first, that has `ItemKey::Lyrics` or else `UnsyncLyrics`; no cover art or properties), cut to the same cap at a char boundary. All inside `panic_guard::quietly`; never writes.
- `state.rs` — pure saved-session model and file format (no I/O; the file is untrusted): `Settings` (volume, shuffle, repeat, visualizer, lyrics; `Default` = first run), per-folder `FolderEntry { resume: Option<Resume>, open }` with `Resume { track: RelPath, item, position, source: SavedSource }`, `Session { settings, folder }` (one run's save), `RootKey` (canonical root bytes, compared exactly), `StateFile { settings, folders }` (most recently used first). `parse(bytes) -> Parsed::{Valid, Newer, Invalid}`: header `kasset-state N` (`FORMAT_VERSION` 1; 0/malformed → `Invalid`, higher → `Newer`), then `key value` lines; settings only before the first `folder`; each value forgiving on its own (first valid value wins, bad escapes/values/unknown keys ignored, `\r` stripped, repeated root ignored, at most `MAX_FOLDERS` 20, volume rounded down to a 5% step, `position-ms` above `MAX_POSITION` (1 week) ignored, a bare `folder` line still ends the entry); checked arithmetic, linear scan. Values are percent-encoded (bytes outside `0x21..=0x7E`, and `%`); paths from raw bytes on Unix, UTF-8 elsewhere (non-Unicode → not saved). `RelPath` = `Normal` components joined with `/`, each non-empty, not `.`/`..`, no `/` or NUL (non-unix: UTF-8, no `\` or `:`); parsed per encoded component so `%2F` is rejected; only ever compared with scanned tracks' relative paths, never joined. Playlist names (`open`, `source playlist`) must be ≤ `MAX_NAME_BYTES` (255) and a valid component by the same rule (control characters allowed, like file names); they are only matched against the listing and sanitised for display. `render` never exceeds `MAX_STATE_BYTES` (64 KiB, the read cap) and only writes what `parse` accepts (positions clamped, invalid names dropped, an invalid source name written as `library`): folders added newest first, one that does not fit is skipped and older ones that fit are kept; a first folder too large alone drops its resume point, then `open`, then itself. `Resume::position` must be built in whole ms so a reloaded session compares equal. `merge(file, root, session, keep)` replaces the settings, puts the root's entry first (removing others for it), uses `keep` when the session has no resume point, cuts to `MAX_FOLDERS`. `state/store.rs` does the I/O: `trait StateStore { load() -> Loaded { settings, folder, newer }, save(session, keep) -> Result<Saved::{Written, Skipped}, String>, persists() }`; `NoState` (loads nothing, saves `Skipped`, `persists() == false`), `FsStateStore::new(file, root)` (root → `RootKey`; `None` saves settings only) and the pure `location(state, local)` (first absolute of the two, + `kasset/state`; tests never call `dirs`). Load: `bounded_read::read_limited` capped at `MAX_STATE_BYTES`, a truncated read drops its last (cut) line; missing, not a regular file, or damaged → empty (a save replaces it), any other read error → empty on load but the save **fails** (never wipes other folders over a transient error). Save: re-read + `merge` (read-merge-write), creates the folder (unix: a new `kasset` folder `0700`, `fchmod` through an `O_NOFOLLOW|O_DIRECTORY` handle; an existing one untouched), sweeps regular (never links or folders) `.state.tmp-*` files older than `STALE_TEMP_AGE` (10 min), writes `.state.tmp-<pid>-<random u64 hex>` with `create_new` (unix `0600`, set explicitly), one retry on a taken name, `sync_all`, `rename` over `state` (replaces a symlink, never writes through it), best-effort dir fsync; the temp file is removed on failure; errors are `cannot save state to <display_path>: <reason>`. A `Newer` file (at load or save) makes every later save `Ok(Skipped)`. Until groups 3–5 wire it in, `main.rs` gates `state` with `cfg_attr(not(test), expect(dead_code))`; remove that once it is used.
- `library.rs` — recursive discovery (`walkdir`, skips unreadable dirs, broken links, loops; dedupes hard links by `(dev, ino)`), tag reading (`read_tagged` opens through `bounded_read::open_regular`, regular files only, and runs lofty inside `panic_guard::quietly`), `lyrics_tag` for the lyrics pane, sorting. `scan` calls `read_track_in(root, path)`: per field tag → inferred → fallback (title: tag → inferred → stem; artist: tag → file-name artist → folder artist → "Unknown"; album: tag → folder album → "Unknown"; number: tag > 0 → inferred); a path not under `root` infers from the file name only, as does the test-only `read_track(path)`. `library/infer.rs` is the pure inference (`infer(relative) -> Inferred`, all strings sanitised, no I/O): leading `\d{1,3}` number (spaced dash, `". "`, or a single space only after a leading `0`; 0 is none; digits-only stems give nothing), artist/title split at the first spaced `-`/`–`/`—` (no split if a side is empty), video labels removed from the title (bracketed groups whose words are all in `LABEL_WORDS`, and a trailing unbracketed run from its first `official`; never left empty), and folders: with ≥ 2 parent folders after skipping a disc-folder parent (`cd`/`disc`/`disk`, optional ` `/`-`/`_`, 1–2 digits), the nearest is the album and the next the artist; a file-name artist wins.

## Testing conventions

- App behaviour is tested as **key sequences** against `App` with fake audio and a `tempfile` store; rendering via `TestBackend`. Shared fixtures (in-memory WAV, `track(...)`, `SilentAudio`, `ToneAudio`, `no_store()`) are in `src/test_support.rs`.
- Forcing write failures must not use `chmod` (root ignores it): make `Playlists` a regular file, or pre-create a directory at the temp path `.<name>.m3u8.tmp-<pid>`. Permission and symlink tests are `#[cfg(unix)]`.
- Existing queue/playback tests must keep passing unchanged when generalising play-order logic.

## OpenSpec workflow

Features are specified and tracked with OpenSpec (`openspec/`, skills under `.claude/skills/`, commands `/opsx:propose|apply|update|sync|archive|explore`).

- Current specs: `openspec/specs/{audio-playback,audio-visualizer,lyrics,music-library,player-tui,playlists}/spec.md`.
- No active change. Design decisions referenced in code: playlists D1–D9 in `openspec/changes/archive/2026-11-17-add-playlists/design.md`, visualizer D1–D9 in `openspec/changes/archive/2026-11-19-add-visualizer/design.md`, lyrics D1–D8 in `openspec/changes/archive/2026-11-19-add-synced-lyrics/design.md`, path inference D1–D5 in `openspec/changes/archive/2026-11-19-infer-metadata-from-paths/design.md`. In a change, `tasks.md` tracks progress by task group; mark tasks `[x]` as they are completed and verified.
- Archived changes live in `openspec/changes/archive/`.
- When adding or changing keys, update `keys::GROUPS` in `src/keys.rs` (it feeds `--help`, the help overlay and the key bar) and the README keys tables together.
