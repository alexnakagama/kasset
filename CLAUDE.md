# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

kasset is a keyboard-driven terminal music player (Rust, ratatui + crossterm UI, rodio audio, lofty tags) for a local music folder. Single binary crate, no workspace.

## Commands

```sh
cargo build                                   # needs libasound2-dev + pkg-config on Linux
cargo run -- [DIR]                            # open DIR (default: XDG music dir, ~/Music, then cwd)
cargo run -- --help                           # key summary lives in src/cli.rs
cargo test                                    # all unit tests (no sound hardware needed)
cargo test queue::                            # tests in one module
cargo test some_test_name                     # single test by name substring
cargo clippy --all-targets -- -D warnings     # must be clean; pedantic is on
cargo +1.89 build                             # MSRV check (rust-version = 1.89)
```

Whenever dependencies change, re-check `rust-version` against the highest dependency MSRV (`cargo metadata`).

CI (`.github/workflows/ci.yml`) runs clippy + tests on Linux, macOS and Windows plus an MSRV build. Releases: bump `version` in `Cargo.toml`, dry-run `gh workflow run Release --ref master` (also runs on PRs touching Cargo.toml/Cargo.lock/.cargo/release.yml; builds + packages, never publishes), then push tag `vX.Y.Z`; `release.yml` checks the tag matches, tests, builds 5 targets and publishes a GitHub Release. Code must stay warning-free on non-unix too (gate unix-only test helpers with `#[cfg(unix)]`). `.cargo/config.toml` links the MSVC C runtime statically so `kasset.exe` needs no VC++ Redistributable.

## Lints and code rules

- `unsafe_code = "forbid"`; clippy `all` + `pedantic` warn, plus `unwrap_used`, `expect_used`, `dbg_macro`, `todo`. Tests avoid `unwrap()` too (e.g. `unwrap_or_else(|never| match never {})`).
- Edition 2024. Every module starts with a `//!` doc comment explaining its role and invariants — keep them accurate when changing behaviour.
- Tags, file names and playlist contents are **untrusted input**. All text that reaches the screen must go through `text::sanitize` / `text::display_path`; decoders and tag readers run inside `panic_guard::quietly` so their panics become errors without printing over the TUI.
- Release profile uses `panic = "unwind"` (required for `catch_unwind` in `panic_guard`).

## Architecture

Data flows `main.rs` → `cli::resolve_root` → `terminal::ensure_terminal` → `Player::open` (fail fast with no audio device) → `library::scan` → `App::new(tracks, player, FsStore, …)` → `App::restore(make_store(cli.no_state, state::store::location(dirs::state_dir(), dirs::data_local_dir()), &root), &root)` (same `root` as the scan; `NoState` with `--no-state` or no known folder) → `terminal::run` event loop (ends with `App::shutdown`) → `finish(app, result)`: `App::save_final()` for every outcome, a failure printed as `kasset: <message>` after the terminal is restored, the result (and so the exit status) unchanged.

Layering, from pure logic outward:

- `queue.rs` — pure play order (shuffle, repeat off/all/one). Plays a list of **items** (library indices, duplicates allowed) addressed by item position. Supports live edits (`remove_item`, `move_item`, `append_items`, `replace_items`); removing the playing item leaves the queue *detached* (it moves on to the removed item's successor, never back).
- `player.rs` — the `Audio` trait plus the rodio-backed `Player`. Everything above it is generic over `A: Audio` so tests use fakes (`test_support::SilentAudio`; `test_support::ToneAudio` reports a sine for the visualizer; `FakeAudio` in `playback.rs` tests can end/fail individual tracks). `Guarded` wraps every decoder: it turns decoder panics into the end of the track and is the visualizer's audio tap — it mixes frames to mono (tracking spans itself, re-reading the format only on a frame boundary) and hands 512-sample batches to the load's `TapBuffer` ring (newest `FFT_SIZE`) with `try_lock`, dropping them when busy, so the audio thread never blocks or allocates. The tap is upstream of the volume; a rate change clears it; each `load` gets fresh `SourceFlags`, so a fresh tap. `Audio::recent_samples` (default `None`) copies it out, with the load's `generation` (`Player` numbers loads); `Playback::recent_samples` passes it through.
- `playback.rs` — `Playback<A>` ties `Queue` to `Audio`: transport commands, auto-advance, skipping unplayable tracks, `Notice` status messages. A `Source` (library, a playlist, or `Artist(usize)` / `Album(usize)` — `browse::Catalog` indices, valid for one run, never saved) defines the current play order's identity (the items always come from the caller); playlist edits/reloads/renames/deletes are forwarded so the playing order stays consistent, and only `Source::Playlist` follows them. Setters `set_volume` / `set_shuffle` / `set_repeat` (`Queue::set_repeat`) restore saved settings. `resume(source, items, item, position, queued: Option<usize>) -> bool` (D5 of persist-session-state, D9 of add-play-queue) loads one track **paused**: the item's, or with `queued` that queued track (the play order's cursor set at `item` without loading it); `resume_queued(track, position)` is the variant with the library as the play order and nothing current. At zero when the tag duration is known and `position` is at or past it; a `SeekFailed` (any kind) at a non-zero start is retried once at zero, other load errors are not; on failure it never skips to another track: nothing current (same list and source, no queued track), `Stopped`, one error notice "Cannot resume '<sanitised title>': <reason>" that is also the stop reason. Invalid `item`/items/`queued` → `false`, nothing changed. Up-next queue (D1–D4 of add-play-queue): `up_next: Vec<usize>` (library indices, duplicates allowed, ≤ `MAX_UP_NEXT` 1000) plays before the play order continues; the track taken from it is `queued_current`, while `queue`'s cursor stays on the play order's track. `current()` = `queued_current.or(queue.current())`; `current_item()` is `None` while queued (so play-order markers turn off); `playing_queued()`, `source_current()` / `source_item()` (the play order's cursor). One private `advance(cause)` serves `next`, `track_ended` and `record_failure`: `Ended` + repeat one keeps a queued track or a non-detached play order track (the queue waits for `n`), else the front of `up_next` is taken (`up_next_taken` += 1), else `queue.next(cause)`, and only when that returns `Some` is `queued_current` cleared (so at the end with repeat off a queued track stays current: `n` says "Already at the last track", its end stops and Space replays it). Failures of queued tracks never count in `failures` (no "(no playable tracks, stopped)" suffix for them); with `up_next` non-empty a failure always moves on to it. `prev` on a queued track: restart if past 3 s and not stopped, else the play order's track from zero (or the queued track again when the play order has nothing current); never re-queued. `stop` keeps `queued_current`; `toggle_pause` from stopped with nothing current starts the first queued track. `play` / `play_source` / `resume` keep `up_next` and clear `queued_current`. Operations (indices validated, `false`/0 and nothing changed when invalid; `up_next_generation` bumped exactly when `up_next` changes): `enqueue(tracks, front) -> usize` (first ones that fit), `remove_queued`, `move_queued` (`from == to` → `true`, no change), `play_queued(pos)` (plays it now, cursor unchanged, not counted in `up_next_taken`), `clear_queued` (a playing queued track keeps playing), `restore_up_next` (capped). Until group 4 wires them, `source_current`, `source_item`, `resume_queued` and `restore_up_next` carry `#[cfg_attr(not(test), expect(dead_code, …))]` (remove it when they get used).
- `playlist.rs` + `playlist/{name,paths,store}.rs` — `.m3u8` files in `<root>/Playlists`. A playlist is kept as **raw lines with their own line endings** so saves only touch edited lines (comments, BOM, CRLF, unmatched entries, missing final newline survive). Non-UTF-8 or oversized files are parsed but read-only. `paths::Resolver` matches entries literal → `\`-as-separator → `canonicalize` (bounded). `store::FsStore` implements the `PlaylistStore` trait: atomic temp-file + rename saves, stamp check to never overwrite external changes (`ChangedOnDisk`), no-clobber create/rename via `hard_link`, symlinked playlists stay links, but only if the link target resolves inside `Playlists/` (else `ReadOnlyReason::LinksOutside`, re-checked in `save`). kasset never writes inside the library folder outside `Playlists/`; the only other file it writes is the per-user state file (`state/store.rs`).
- `bounded_read.rs` — the one reader for small untrusted files (playlists, `.lrc` sidecars): `read_limited(path, limit) -> (bytes, truncated, Metadata)` opens with `open_regular` (unix: `O_NONBLOCK|O_NOCTTY|O_CLOEXEC`, so a FIFO never blocks; elsewhere a regular-file check first), refuses anything but a regular file judged from the open handle, and reads at most `limit` bytes. The playlist store builds its `FileStamp` from the returned `Metadata`.
- `app.rs` — all UI state and key → action mapping, no terminal I/O; files only via `PlaylistStore`. `Focus` = Sidebar / Main, moved with `Tab`/`BackTab`; `view()` (the list keys act on) is derived from `focus` and `main_view()`: the sidebar (`Playlists`), the library, the open playlist, or a browse level (`Groups` for artist/album lists, `Tracks` for browsed tracks). The sidebar `ListState` has `FIXED_ROWS` (4) fixed rows, "Library" / "Artists" / "Albums" / "Queue" at values 0 / 1 / 2 / 3 (never filtered out; playlist `i` is value `i + FIXED_ROWS`; values ↔ entries only through `SidebarEntry::of_value` / `value()`, wrapped by `selected_playlist()` / `sidebar_value_of()`; `apply_filter` selects the first playlist row; tests use `SidebarEntry::value`, never hard-coded playlist values). Main pane (D4 of add-artist-album-browsing, D6 of add-play-queue): at most one of `open: Option<OpenPlaylist>`, `browse: Option<BrowseRoot>` (Artists / Albums) and `queue_shown` is set (debug-asserted in `main_view()`); only `show_library` / `show_playlist` / `show_browse` / `show_queue` set them. `App::new` builds the `browse::Catalog` once; `artists_nav` / `albums_nav` are stacks of `BrowseLevel { kind: BrowseKind, tracks, list }` (bottom: the artist / album list, never popped; kept while something else is shown, so `Enter` on "Artists" returns to the same place). `BrowseKind`: `Artists` (rows = artist indices), `ArtistAlbums(a)` (value 0 = "All tracks" `ALL_TRACKS_VALUE`, `i + 1` = `albums()[i]` via `artist_album_of_value`, never filtered out, `apply_filter` selects the first album), `Albums`, `Album(b)` / `ArtistTracks(a)` (rows = positions in `tracks`, copied from the catalog on push; `browse_tracks()`). `Enter` on a group row pushes a level (`BrowseLevel::child`). Going back (D5): `Esc` clears a filter, else pops, else (a shown playlist, the queue or the bottom browse level) focuses the sidebar with that entry selected (`focus_sidebar` / `refresh_playlists` take `Option<SidebarPick>`, `SidebarPick` = Library / Artists / Albums / Queue / Playlist(name)); `Backspace` in Normal mode with the main pane focused pops (filter or not), else nothing; Search and NameInput keep Backspace for text. Popping drops the level with its filter; the parent's `ListState` was never touched, so it reselects the opened entry. Level filters: artists by name, albums by `title\nartist`, tracks by the library's search keys. Playing (D6): `Enter` on a browsed track → `play_source(Source::Album(b) | Source::Artist(a), level.tracks, position)` (`play_browsed`); `sidebar_playing` maps them to values 1 / 2 (an album reached through Artists still marks "Albums"); `browse_row_playing(kind, value)` (only while a track is loaded and not queued): album row ⇔ `Album(b)`, artist row ⇔ `Artist(a)` or an album of `a`, "All tracks" ⇔ `Artist(a)`, track row ⇔ the level's own source and `current_item()`. Adding (D7): `a` on a group row → `selected_group_tracks` (album order / `artist_tracks`; no row → nothing), `a` / `A` in a track list → selected / listed (`listed_browse_tracks`); `Picker::tracks` are in the order to add. Up-next queue (D6–D8 of add-play-queue): `View::Queue` / `MainView::Queue` list `queue_list` (rows = positions in `playback.up_next()`, kept with its filter while hidden); `sync_queue_view` runs at the start and end of `handle_key` and at the end of `tick`, refilters only when `up_next_generation` changed, and moves the selection up by the growth of `up_next_taken` (the queue's own edits then set it: `d` / `Enter` same row clamped, `J`/`K` the moved entry, `E` the same entry `added` positions down). Queue view keys: `Enter` → `play_queued`, `d` → `remove_queued`, `J`/`K` → `move_queued` (refused while filtered, "Clear the filter (Esc) to reorder"), `a`/`A` → picker, `Esc` → filter, then sidebar on "Queue"; `Backspace` nothing. `e` / `E` (`enqueue_selected`) in `View::Library`/`Playlist`/`Tracks` (selected track) and `View::Groups` (`selected_group_tracks`), nothing in the sidebar or the queue view; `Info` notices `Queued '<title>'` / `Playing next: '<title>'` / `Queued N tracks` / `N tracks play next` / `Queued K of N tracks; the queue is full (1000)` / `The queue is full (1000 tracks)`. `D` on "Queue" (non-empty only) → `Mode::ConfirmClearQueue`: `y` → `clear_queued` ("Cleared the queue (N tracks)"), any other key cancels ("The queue was not cleared") and is consumed; `R` there does nothing. Markers (D8): `sidebar_playing` gives "Queue" while `playing_queued()`, `browse_row_playing` is `false` for every row then, playlist entries turn off through `current_item()`, the library marks `current()`. `open` is set only by `Enter` on a sidebar playlist and cleared by `Enter` on another sidebar entry, deleting it, or its file vanishing; renaming it reloads it under the new name. Playlists are listed in `App::new` and on every sidebar focus; the app's own edits patch the sidebar entry with `update_info`. Every status message goes through `App::notify` (within one key press an error is never hidden; same-level notices are joined). Each list keeps its own filter and selection. `Mode` = Normal / Search / Picker (add-to-playlist target) / NameInput (`NamePurpose::Create` for "New playlist…" or `NamePurpose::Rename` for `R`, prefilled with the current name) / ConfirmDelete (`D`: `y` deletes, any other key cancels) / ConfirmClearQueue (`D` on "Queue") / Help (`?`: scroll keys move it, clamped to `keys::help_line_count() - help_rows`, where `help_rows` is fed from `ui::View` by `terminal::run` like `page_size`; any other key closes it and is consumed). Entry edits (`d`, `J`/`K`) are made on a copy of the open playlist, saved, then installed, so a failed or conflicting save leaves the screen unchanged. Visualizer state (`Visualizer`): `on` (start on; `v` in Normal mode toggles it, with an `Info` notice only while `!fits`), `fits`/`bars` fed back via `set_spectrum_layout`; `tick` runs the `Spectrum` only while `on && fits && bars > 0` (else resets it), passing samples only while `Playing` and the tap's `(generation, written)` changed within `STALE_AFTER` (250 ms). `visualizer_animating()` drives the frame rate. Lyrics state (`LyricsPane`): `on` (start on; `l` in Normal mode toggles it, with an `Info` notice only while `!fits`, naming `ui::LYRICS_MIN_WIDTH` 100), `fits` fed back via `set_lyrics_layout`; `tick` (after `playback.tick`) calls `lyrics::source::load` only while `lyrics_shown()` (`on && fits`) and the current track's **path** differs from `loaded_for` (seek/pause/replay never re-read); `loaded_for`/`lyrics` are dropped whenever the pane stops being shown, so showing it again re-reads. `lyrics_ready()` (cache belongs to the current track's path) gates `lyrics()`, so "No lyrics" never flashes before a load. `lyrics_generation()` counts loads (for the UI's wrap cache). `lyrics_deadline(now)`: while shown, `now` if a read is due (current track, `!lyrics_ready()`, so widening/showing never leaves the pane blank for a frame), else while `Playing` and synced, `now + max(next_change - position, LYRICS_MIN_WAIT)` (10 ms). `#[cfg(test)] set_lyrics_on` sets `on` with no notice. Saved session (`SavedState`, D4–D6 of persist-session-state): `App` holds a `Box<dyn StateStore>` (`NoState` from `App::new`, so tests never touch a real file). `App::restore(store, root)` (once, before the first tick; `root` is the canonical root, resume tracks are matched by `strip_prefix(root)` → `RelPath` against the scanned tracks only): settings first (no notices), then `open` if listed (`open_named`, main focus, selected in the sidebar), then the resume point via `Playback::resume`; the source is the saved playlist only if listed, or the saved artist / album if `Catalog::find_artist` / `find_album` (by key, ignoring case) has it, and it still holds the track (the saved `item` if it still is that track, else the first match; a non-shown playlist is loaded only for its items), else the library; the browse location is never restored. A resume point that did not resume is kept as `pending` (passed as `keep` to every save) until a track is current. A `newer` load gives one `Info` notice and disables saving. `session()` saves `Detached` as the library (item = library index), `Artist(a)` / `Album(b)` by catalog names (`SavedSource::Artist(name)` / `Album { artist, title }`, item = `current_item()`), position in whole ms. `tick` (first, via `autosave`) checks at most every `SAVE_INTERVAL` (30 s, first tick arms it), saves only if `session()` differs from the last saved/restored one; the first failure is notified (capitalised, sanitised), later ones only after a success; `Saved::Skipped` turns saving off. Nothing is built while saving is off (`persists() == false` or newer). `shutdown` takes the final session before `stop` and writes nothing; `save_final() -> Option<String>` writes it once (no-op without `shutdown`). Entry points: `App::handle_key`, `App::tick`.
- `browse.rs` — pure artist/album grouping (D1 of add-artist-album-browsing), built once per run; its indices are valid only within that run (never persisted). `Catalog::build(&[Track])`: every track in exactly one `Album { title, artist, tracks }` keyed by (album artist key, title key), album artist = non-empty `album_artist` else `artist`, keys `to_lowercase()`, display text = first spelling in library order (track text is already sanitised). Albums sorted by (artist key, title key); `Artist { name, albums, track_count }` sorted by key, each artist's albums a contiguous run sorted by title key; only album artists are listed (a guest track artist is not). Album track order: disc (missing = 1), number (unnumbered last), title lower-cased, path, index. `artist_tracks(a)` concatenates the artist's albums (built per call, empty for an unknown index). `find_artist(name)` (binary search by key) / `find_album(artist, title)` find a saved source again by name, `to_lowercase()`-compared, untrusted input only compared. `search_key()`: artist name; album `title\nartist`, lower-cased.
- `ui.rs` — renders `App` read-only. Body = sidebar + main pane at ≥ `TWO_PANE_MIN_WIDTH` (70) columns, else only the focused pane full width; draws from `sidebar_list()` / `main_list()`, never `visible()`/`selected()` (those are the focused list only). `ui::View` keeps `sidebar_offset` / `main_offset` (the sidebar's offset counts playlist rows; the fixed rows "Library" / "Artists" / "Albums" / "Queue" (with track / artist / album / queued-track counts, `fixed_row_counts`) and the separator stay on top: in a short pane the fixed rows are cut from the bottom, the separator is drawn only with a playlist row below it, and the fed-back page counts playlist rows only) and feeds back `page_size` (focused pane), `help_rows`, `spectrum_fits` / `spectrum_bars`, and `lyrics_fits` (width ≥ `LYRICS_MIN_WIDTH` 100, set every frame whether or not the pane is on). Lyrics pane: a third column right of the main pane when `app.lyrics_on()` and `lyrics_fits`, width `(body/3).clamp(LYRICS_WIDTH)` (28..48); the sidebar keeps its two-pane width, the main pane fills the rest; above the strip; never focused (unfocused border). It shows "Nothing playing" with no current track, nothing while `!app.lyrics_ready()`, "No lyrics" (both via `render_empty`), else `lyric_rows(lyrics, width)` — wrapped by drawn width (sum of grapheme-cluster widths) at spaces, over-wide words broken between clusters — cached in `View::lyrics_rows` keyed by `(App::lyrics_generation(), inner width)`; per frame only `current_rows` (`partition_point`) and `row_role` are computed: `PLAYING` (current line, all its rows) / `DIM` (past) / default. Synced scroll centres the whole current line (`synced_top`; its first row on top if taller than the pane), plain scroll is `span * pos_ms / dur_ms` in `u128` clamped to `span` (`plain_top`). Spectrum strip: the bottom `SPECTRUM_HEIGHT` (6) rows of the body when `app.visualizer_on()` and height ≥ `SPECTRUM_MIN_HEIGHT` (24), full width at every width, unfocused border, `bars = (inner_width + 1) / 2` (1-column bars, 1-column gaps), draws `min(levels.len(), bars)` bars in eighths (`█`, `▁…▇`) with `theme::SPECTRUM`. Browse levels (`MainView::Browse(kind)`): `render_browse` titles the pane by the level (album: `title · artist`, artist tracks: `artist · All tracks`, elided at the end by `plain_title`; counts via `count_title`, "All tracks" listed but not counted); an empty level says "No artists" / "No albums" / "No tracks" (`render_empty`, no header), no match "No <noun> match '<q>'". `render_browse_rows` draws group levels as tables with a header through `render_groups` (`Column` specs: `ARTIST_COLUMNS` name / Albums / Tracks, `ARTIST_ALBUM_COLUMNS` title / Tracks with "All tracks" first counting the artist's tracks, `ALBUM_COLUMNS` title / album artist / Tracks; counts right-aligned, header included; rows from `group_row`) and track levels with `render_tracks` (the library's columns). Every row's marker and `PLAYING` style come from `App::browse_row_playing(kind, value)`, so a browsed track is marked only when its level's album/artist is the play order. Sidebar marker comes from `App::sidebar_playing()` (only while a track is loaded; "Queue" while a queued track is current). Queue view (`MainView::Queue`, interim until task 5.1 of add-play-queue): `render_queue` titles it "Queue" with `pane_count`, the library's columns over `up_next()` positions, no playing marker, "Queue is empty" / the library's no-match text via `render_empty`; `Mode::ConfirmClearQueue` has no popup yet, only its key bar. Popups centre over the whole body (panes and strip together); the `?` overlay centres over everything above the status line, sized to its widest line, and writes `help_rows` only while drawn. Now-playing is 3 rows (top rule, track line with right-aligned indicators that win over the title, custom `━╸─` progress line). The key bar is drawn from `keys::bar(context)`, cut at whole labels, `? help` right-aligned in Normal mode only. All styles come from `theme.rs` — no `Color`/`Modifier`/`Stylize` in `ui.rs` outside tests. Tested with ratatui `TestBackend`.
- `keys.rs` — the single key table `GROUPS` (D7) feeding `--help` (`help_text`), the help overlay (`help_lines`) and the key bar (`bar(BarContext)`). Normal-mode contexts (`BarContext::is_normal`, bar ends with `? help`): `Library`, `Playlist`, `Sidebar`, `BrowseTop` (artist/album list: `Enter open`, `Esc sidebar`, `a add`), `BrowseGroups` (an artist's albums: `Esc back`), `BrowseTracks` (`Enter play`, `a/A add`, `Esc back`), `Queue` (`Enter play`, `d remove`, `J/K move`, `Esc sidebar`; no `e/E queue`); `ui::bar_context` picks the browse one from `View::Groups`/`Tracks` and `browse_depth()`, and `Queue` for `View::Queue`. `Library`, `Playlist` and `BrowseTracks` also show `e/E queue`. Prompt contexts include `ConfirmClearQueue` (`y clear`, `any other key cancel`). The "Browse" group (`Esc / Backspace`, `a`) follows "Sidebar & playlists", then the "Queue" group (`e / E`, `Enter` in the queue); `d`, `J / K`, `Esc` and `D` name the queue too; each view's own labels precede `Space pause` (tested).
- `theme.rs` — style roles (D8): `PLAYING`, `SELECTED_FOCUSED`/`SELECTED_UNFOCUSED`, `BORDER_*`, `DIM`, `ERROR`, … Named ANSI colours only; each colour has one meaning.
- `terminal.rs` — raw mode / alt screen setup and restore on every exit path (quit, error, signal, panic); redirects fd 2 to `/dev/null` while the UI is up so ALSA can't print over it. A second identical signal is an emergency exit. Each frame: tick, draw, feed back `page_size` / `help_rows` / `set_spectrum_layout` / `set_lyrics_layout`, then poll input until `next_deadline(frame_start, app.visualizer_animating(), app.lyrics_deadline(now))` — `ANIMATION_FRAME` (33 ms) while animating, else `FRAME` (250 ms), counted from the frame start, or the lyric deadline (next synced line, or at once while a lyrics read is due) if that is earlier.
- `visualizer.rs` — pure spectrum analysis (`rustfft`): `Spectrum::update(samples+rate, bars, now)` windows the newest `FFT_SIZE` (2048) mono samples, takes peak magnitudes in log-spaced bands from 40 Hz to `min(16 kHz, rate/2)`, maps −60…0 dB to 0…1; bars rise at once and fall linearly over `FALL_TIME` (1 s); a bar-count change resets the levels (count clamped to `MAX_BARS`). DC offset is removed and bin 0 never used. Levels are always finite and in `0..=1`.
- `lyrics.rs` — pure LRC parsing (no I/O): `parse(text) -> Option<Lyrics>` gives `Lyrics::Synced(Vec<Line { at, text }>)` (sorted by time, stable for equal times; one `Line` per leading `[mm:ss(.x{1,3})]` stamp, 1–6 minute digits) or `Lyrics::Plain(Vec<String>)` (file order, blank edges trimmed). `[tag:value]` headers (tag of ASCII alnum/`_`/`-`/`#`) are skipped before a timestamp; an untimed line is dropped only if it is nothing but `KNOWN_TAGS` headers (`ar`, `ti`, `offset`, …), so `[Chorus: Singer] la` stays text; `[offset:±N]` shifts times (positive = earlier), clamped to ±1 h, saturating at 0; other bracket text (`[Chorus]`) stays; `<mm:ss.xx>` word timings are stripped. With any timestamp, untimed lines are dropped; blank timed lines are kept as `""` (they end the previous line). Every text goes through `text::sanitize` (whitespace collapsed, cut to `MAX_TEXT_CHARS` 256); at most `MAX_LINES` (10 000) lines; arithmetic is checked/saturating and scanning linear, so crafted input can't panic, wrap or stall. `current(pos)` / `next_change(pos)` use `partition_point`. `lyrics/source.rs` does the I/O: `load(track) -> Option<Lyrics>` reads the first *readable* sidecar (`<stem>.lrc`, `<stem>.LRC`, then a sorted, case-insensitive-extension match from at most `MAX_DIR_ENTRIES` (10 000) folder entries; a directory/FIFO/dangling link counts as absent) through `bounded_read` capped at `MAX_LYRICS_BYTES` (1 MiB), decodes it (UTF-8 BOM, UTF-16 LE/BE BOM, else lossy UTF-8), and parses it even if that gives `None` (an empty sidecar hides tag lyrics); a truncated sidecar loses its last (possibly cut) line (split at `\n` or `\r`); without one it falls back to `library::lyrics_tag` (raw text of the first tag, primary first, that has `ItemKey::Lyrics` or else `UnsyncLyrics`; no cover art or properties), cut to the same cap at a char boundary. All inside `panic_guard::quietly`; never writes.
- `state.rs` — pure saved-session model and file format (no I/O; the file is untrusted): `Settings` (volume, shuffle, repeat, visualizer, lyrics; `Default` = first run), per-folder `FolderEntry { resume: Option<Resume>, open, queue: Vec<RelPath> }` with `Resume { track: RelPath, item, position, source: SavedSource, queued: Option<RelPath> }` (with `queued`, `track`/`item`/`source` are the play order's track the queued track played after and `position` is the queued track's), `Session { settings, folder }` (one run's save), `RootKey` (canonical root bytes, compared exactly), `StateFile { settings, folders }` (most recently used first). `parse(bytes) -> Parsed::{Valid, Newer, Invalid}`: header `kasset-state N` (`FORMAT_VERSION` 1; 0/malformed → `Invalid`, higher → `Newer`), then `key value` lines; settings only before the first `folder`; each value forgiving on its own (first valid value wins, bad escapes/values/unknown keys ignored, `\r` stripped, repeated root ignored, at most `MAX_FOLDERS` 20, volume rounded down to a 5% step, `position-ms` above `MAX_POSITION` (1 week) ignored, a bare `folder` line still ends the entry; `queue <relpath>` lines (D9 of add-play-queue) each read on their own, at most `playback::MAX_UP_NEXT` kept, later ones not even decoded; `queued-track <relpath>` first valid wins, kept only with a `track`; older versions ignore both, so `FORMAT_VERSION` stays 1); checked arithmetic, linear scan. Values are percent-encoded (bytes outside `0x21..=0x7E`, and `%`); paths from raw bytes on Unix, UTF-8 elsewhere (non-Unicode → not saved). `RelPath` = `Normal` components joined with `/`, each non-empty, not `.`/`..`, no `/` or NUL (non-unix: UTF-8, no `\` or `:`); parsed per encoded component so `%2F` is rejected; only ever compared with scanned tracks' relative paths, never joined. Playlist names (`open`, `source playlist`) must be ≤ `MAX_NAME_BYTES` (255) and a valid component by the same rule (control characters allowed, like file names); they are only matched against the listing and sanitised for display. `SavedSource` is `Library`, `Playlist(name)`, `Artist(name)` or `Album { artist, title }`, written `source library` / `playlist <enc>` / `artist <enc>` / `album <enc> <enc>` (two fields, one space; encoded values never hold one); artist/album names must be non-empty UTF-8 ≤ `MAX_GROUP_NAME_BYTES` (1024 = 4 × `MAX_TEXT_CHARS`), `/` and control characters allowed (not file names), only compared with the catalog's names, never paths. An unknown `source` value is ignored (default library), so older versions read artist/album sources as the library and `FORMAT_VERSION` stays 1. `render` never exceeds `MAX_STATE_BYTES` (64 KiB, the read cap) and only writes what `parse` accepts (positions clamped, invalid names dropped, an invalid source name written as `library`, at most `MAX_UP_NEXT` queue lines): an entry is resume lines (`queued-track` last), `open`, then `queue` lines; folders added newest first, each with the longest prefix of its queue that fits (`push_queue`, one pass, possibly empty); one that does not fit without its queue is skipped and older ones that fit are kept; a first folder too large alone drops its queue, then its resume point, then `open`, then itself. `Resume::position` must be built in whole ms so a reloaded session compares equal. `merge(file, root, session, keep)` replaces the settings, puts the root's entry first (removing others for it), uses `keep` when the session has no resume point (the resume point only: the queue and `open` always come from the session), cuts to `MAX_FOLDERS`. `state/store.rs` does the I/O: `trait StateStore { load() -> Loaded { settings, folder, newer }, save(session, keep) -> Result<Saved::{Written, Skipped}, String>, persists() }`; `NoState` (loads nothing, saves `Skipped`, `persists() == false`), `FsStateStore::new(file, root)` (root → `RootKey`; `None` saves settings only) and the pure `location(state, local)` (first absolute of the two, + `kasset/state`; tests never call `dirs`). Load: `bounded_read::read_limited` capped at `MAX_STATE_BYTES`, a truncated read drops its last (cut) line; missing, not a regular file, or damaged → empty (a save replaces it), any other read error → empty on load but the save **fails** (never wipes other folders over a transient error). Save: re-read + `merge` (read-merge-write), creates the folder (unix: a new `kasset` folder `0700`, `fchmod` through an `O_NOFOLLOW|O_DIRECTORY` handle; an existing one untouched), sweeps regular (never links or folders) `.state.tmp-*` files older than `STALE_TEMP_AGE` (10 min), writes `.state.tmp-<pid>-<random u64 hex>` with `create_new` (unix `0600`, set explicitly), one retry on a taken name, `sync_all`, `rename` over `state` (replaces a symlink, never writes through it), best-effort dir fsync; the temp file is removed on failure; errors are `cannot save state to <display_path>: <reason>`. A `Newer` file (at load or save) makes every later save `Ok(Skipped)`.
- `library.rs` — recursive discovery (`walkdir`, skips unreadable dirs, broken links, loops; dedupes hard links by `(dev, ino)`), tag reading (`read_tagged` opens through `bounded_read::open_regular`, regular files only, and runs lofty inside `panic_guard::quietly`), `lyrics_tag` for the lyrics pane, sorting. `scan` calls `read_track_in(root, path)`: per field tag → inferred → fallback (title: tag → inferred → stem; artist: tag → file-name artist → folder artist → "Unknown"; album: tag → folder album → "Unknown"; number: tag > 0 → inferred; `album_artist` (`ItemKey::AlbumArtist` via `tag_item_text`/`Tag::get_string`, sanitised) and `disc` (`Accessor::disk` > 0) come from tags only, never inferred); `sort_tracks` orders by artist, album, disc (missing = 1), number (missing last), title, path; a path not under `root` infers from the file name only, as does the test-only `read_track(path)`. `library/infer.rs` is the pure inference (`infer(relative) -> Inferred`, all strings sanitised, no I/O): leading `\d{1,3}` number (spaced dash, `". "`, or a single space only after a leading `0`; 0 is none; digits-only stems give nothing), artist/title split at the first spaced `-`/`–`/`—` (no split if a side is empty), video labels removed from the title (bracketed groups whose words are all in `LABEL_WORDS`, and a trailing unbracketed run from its first `official`; never left empty), and folders: with ≥ 2 parent folders after skipping a disc-folder parent (`cd`/`disc`/`disk`, optional ` `/`-`/`_`, 1–2 digits), the nearest is the album and the next the artist; a file-name artist wins.

## Testing conventions

- App behaviour is tested as **key sequences** against `App` with fake audio and a `tempfile` store; rendering via `TestBackend`. Shared fixtures (in-memory WAV, `track(...)`, `SilentAudio`, `ToneAudio`, `no_store()`) are in `src/test_support.rs`.
- Forcing write failures must not use `chmod` (root ignores it): make `Playlists` a regular file, or pre-create a directory at the temp path `.<name>.m3u8.tmp-<pid>`. Permission and symlink tests are `#[cfg(unix)]`.
- Existing queue/playback tests must keep passing unchanged when generalising play-order logic.
